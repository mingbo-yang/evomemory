EvoScope 零更新诊断（2026-09-26）

本次只分析既有代码和六组实验的学习、Probe、编辑及 Gate 记录，没有调用模型、修改运行参数或更新记忆库。GLM 的最终测试仍在运行时，其学习和 Gate 阶段已结束，足以诊断零更新；测试得分未用于挑选新条件或验证任务。

**结论**

零更新不是一个单独的 Gate 阈值问题。六组共 36 次 checkpoint 探测得到 30 neutral、4 harmful、2 helpful；跨模型复用了一些任务，不能把 36 次视为 36 个独立任务。生成了 5 个候选；5 个候选全部在 Gate 打平，没有正收益候选被阈值挡住。主要问题依次是验证覆盖失效、采样实现与小预算组合产生偏置、编辑证据孤立，以及 Probe 与正式条件策略的干预差异。修复这些问题可能改善信息质量，但不保证出现有效更新。

1. GLM WebShop 的 Gate 没有测试到被修改的记忆。

候选将 p01 的条件从商品列表页改为商品详情页。两个 Gate 任务是紫色化妆刷和无线充电器；12 条新旧验证轨迹均未检索到 p01。六对 rollout 的模型请求 hash 序列完全一致。因此这一 Gate 只测到了未受影响的任务，新旧同分无法说明修改有无价值。

代码原因：engine.py 的 evolve 直接按列表取剩余 Gate 任务前 N 个，没有任何目标记忆覆盖检查。正 BM25 阈值没有出错；不能靠重新塞入零相关记忆“修好”这个问题。目标未出现的任务可作为总体回归样本，但不应被误认为覆盖了修改。

2. 一次一个采样名额时，所谓成功/失败分层退化为成功优先。

sample_checkpoints 每次从 success 层开始；实验全局 Probe 预算是 6、每条策略 3，均匀调度后每个有名额的轮次只有 1 个。六组中有 24 个轮次同时存在成功、失败候选，但 24 次全部选成功。Qwen3.8 ALFWorld 六次 Probe 全来自成功轨迹，六轮都存在可选失败轨迹。

这不是不能采失败：没有成功候选时确实会选失败。问题是跨批次没有记住层配额，从而不满足整个实验的平衡覆盖目的。

3. 五个编辑候选全部只用了一个 checkpoint 的证据。

engine.evolve 只把本轮 rows 交给 propose，历史证据虽已保存，却没有进入后续编辑调用。三次重复是同一状态的重复，不是三个不同情境。

出现的候选包括 Qwen9B 将一般搬运条件改成“pencil is in inventory ...”；GLM 将一般搜索条件追加“no remotecontrol is on armchair”。这些修改包含具体对象，存在对单轨迹过拟合风险；不能仅凭字符串就判定无效，但不支持已学到可推广的 scope 边界。

4. Probe 测到的是持续提供裸策略的效果，不直接等于原 when 的缺陷。

runner 在 checkpoint 之后的每一步都持续 expose/mask；expose 去掉 when，即使目标后来不再被正常检索到仍强制注入。ALFWorld expose 步骤中，目标已掉出正常检索结果的比例分别为 Qwen3.8 123/222、Qwen9B 168/378、GLM 420/540。所有三组 ALFWorld 的 100 条学习任务、两条记忆都在 step 0 首次被检索，因此当前 clean Probe 只能检查初始状态。

四个 harmful 案例中，三个原始带 when 的学习轨迹成功且动作序列与 mask 分支完全相同，而 expose 失败。这表明原条件有可能已经阻止了裸策略造成的干扰。原始学习与 Probe 的调用种子不同，虽然本地为 temperature=0，仍不能把它当成严格同种子的第三对照；它是需要补查的强证据，而不是最终因果证明。

现有协议本来就规定持续干预，因此这不是实现偏离文档的 bug。要改干预持续时间、只在仍被检索时 expose，或者加入 normal 分支，都应登记为新实验协议。

5. neutral 多数不是“记忆没作用”，而是奖励相同。

30 个 neutral 状态中，26 个 expose/mask 的完整动作轨迹不同，但最终得分一致。36 个 checkpoint 内三次重复的每个分支动作序列都完全相同。本轮重复提高了复现证据，却没有增加独立状态覆盖。

Gate 30 对执行中 21 对动作完全相同；其余 9 对动作不同仍同分。Qwen9B 一个任务从 16 步变成 15 步但都是成功，GLM 两个任务动作改变但都是失败。不能为了接受更新，事后把步骤数改为优化目标；可以作为诊断项记录。

6. 初始库规模与任务规模不匹配是限制，尚不能单独断言为根因。

每个数据集 M0 仅两条基础策略。ALFWorld 是搜索与搬运，WebShop 是搜索与尺寸选择。do 不可修改，when 修改不能修复错误的行动核心或补足模型本身的执行能力。原策略中抽象描述有时被 GLM 当成字面动作输出，例如“search adjacent containers and locations”。但不能由此断言所有失败都来自 M0；需要独立检查自然生成策略的可操作性。

**建议的最小修复顺序**

第一步，修复采样和编辑证据组织，不增加新的学习模块。

- 每条策略跨轮次维护成功/失败配额，单名额优先补足欠采层；平局按预先固定的交替顺序处理。按策略报告实际覆盖，不根据 Probe 正负效果选样本。
- 编辑时累积同一策略、同一 bank 版本的公开证据，包括 neutral 与失败记录；不混入 Gate/test 轨迹。用不同状态建立条件边界，避免一个状态就产生一个专有名词补丁。编辑时机预先固定，不能看到哪个条件过 Gate 就选哪个。
- 对这些变化做针对性回归检查：六个单名额且两层都非空时，应近似平衡；编辑输入包含多个同版本状态且无验证轨迹。

第二步，让 Gate 的覆盖可核查，保留严格正提升接受规则。

- 在候选评分前，依据固定初始 bank、公开任务信息和预先声明的检索覆盖规则，从独立 Gate 池选择有目标曝光的任务；保持 one task per group。需要 rollout 的预运行属于验证资源消耗，也要记录。
- 仍保留固定抽取的总体回归任务，并单独报告受影响任务覆盖。不能仅挑候选得分提升的任务，也不能因为一次打平就反复换题直至接受。
- 可以预注册每候选 4 个独立任务，替代当前 2 个；WebShop 仅 10 个 Gate 组时，最多支持两次这样的候选验证，其余预算不足要明确结束，不能重复用组。
- 目标完全未曝光时标记“覆盖不足”，不能声称已充分证明候选无效。更大的样本也不能保证候选有益。

第三步，用很小的同种子诊断验证 Probe 与 when 编辑是否一致。

- 对已留出的学习状态比较 normal（保留原 when）、expose（裸 do）、mask。旧学习轨迹可辅助离线分析，但不能取代同 checkpoint、同配置、同种子的 normal 对照。
- 如果 normal 与 mask 都成功、expose 失败，应首先判断原条件是否已发挥作用，不能把这个状态当成必须修原条件的证据。
- 这是一项新增诊断，不应立即叠成复杂训练流程。如果发现持续裸策略干预是主要信号来源，再决定是否更改干预范围；那属于方法协议调整，须单独验证。
- 晚期状态若目标已经 seen，不能直接当 clean checkpoint。若确需阶段覆盖，需从开始屏蔽目标产生可恢复前缀，这是下一步研究设计，不是可悄悄放宽的检查。

第四步，再决定扩大自然 M0 与 Probe 预算。

先修前两项，用小规模 Phase 1 看“覆盖→行为变化→奖励变化”是否改善，再决定是否从更多 bootstrap 训练轨迹自然生成更丰富 M0。所有对比组共享同一个新 M0，禁止手写错误 scope。保留旧 M0 诊断，以区分初始化变化和演化收益。若改为 24 个 Probe，总预算与每条策略上限必须共同配置；当前只有两条策略、每条上限 3 时，总上限提高到 24 仍只能执行 6 次。

不建议放宽为平分也接受、不建议临时加步骤奖励、不建议看到 Gate 失败后不断换题。若修复覆盖和证据组织后仍无效果，应接受该初始化/模型/任务组合下没有 scope 演化收益的结论。

**附带工程问题（不是五个候选被拒的原因）**

GLM WebShop 两条测试 ValueError 是行动 JSON 带了多余字段：一条有 policies，另一条有 policy；后者还输出了未实例化 search[<keywords>]。一次学习 HTTP 400 是输入加预留输出超出上下文 1 token。下一协议应统一 action-only 输出约束及基于真实 tokenizer 的输入预算处理；不要静默吞字段、重试直到成功或只修 EvoScope 一组。五个 Gate receipt 本身都没有执行错误。
