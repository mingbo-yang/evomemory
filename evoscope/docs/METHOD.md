# EvoScope：基于成对执行证据的策略适用范围进化

> EvoScope 概念方法说明（原稿 2026-09-24）。当前实验协议以 [PROTOCOL_V3.md](PROTOCOL_V3.md) 和实际代码为准。旧方法已移出项目，仅在 `/mnt/huawei/ymb/backups/evomemory-legacy-20260926/` 留档，不作为实验分支或基线。

## 1. 研究问题

同一条经验策略可能在部分状态中有帮助，在另一些状态中有害。与其反复增加规则或重写整条策略，EvoScope 根据可恢复的真实执行分支，修正“什么时候应该使用这条策略”。

核心贡献候选是**策略适用范围的证据驱动进化**：以同一决策点上的成对干预定位收益边界，以条件编辑表达边界，以独立完整库验证决定继承。只修改 `when` 是控制自由度和便于归因的约束，不单独包装为创新。

## 2. 策略表示与执行

策略包含 `id / key / when / do / version / evidence_ids`。`key` 是固定检索文本，`do` 是固定动作建议；进化只更新 `when`、版本及证据引用。不存在短中长期分层、晋升次数或全局策略质量分。

正常任务在 `key + do` 上用固定 BM25 检索最多 3 条正分记忆，无匹配时返回空集；检索查询始终保留从初始公开观测提取的真实任务目标，Actor 接收 `when + do`。条件必须由执行前的可见目标和历史支持；不确定时不应当作成立。`when` 统一限制为 400 字符，初始抽取提示要求 `do` 不含适用条件、分支或例外。当前实现由同一 Actor 解释条件，没有额外选择器。自然语言条件是否严格合规仍需审查，程序只硬性限制输出字段及动作核心不变。

## 3. 证据生成

正常任务成绩先独立记录。按固定顺序轮询策略，从成功或失败任务中选取该策略首次进入上下文之前的 checkpoint，不把“实际采用过这条策略”设为入选条件。按成功/失败交替分层抽样、不足补齐，每条轨迹最多一个 checkpoint；记录可用数与抽样数。

从同一任务、环境种子和动作前缀恢复状态，逐步检查可见结果。无法恢复、已暴露目标、配置摘要不符时跳过，不生成想象的反事实。

在同一 checkpoint 上执行两支：

- 暴露支：移除目标原条件，只提供固定动作核心 `do`。
- 屏蔽支：移除目标，不用下一条策略补位。

其他配置相同，后续持续维持干预槽位，保留目标在 checkpoint 中的检索排位。默认重复三次并交替执行次序。记录每支真实回报、公开轨迹及成对差值；同号非零的差值才标记有帮助或有害，全零标记 neutral，其余不一致结果标记 unstable；恢复失败及执行失败分别记录。分支结果不回填首次成绩。

当前 ALFWorld 恢复方式是重置加动作回放，适用于可确定回放的 TextWorld 游戏；可见状态一致不能作为任意随机环境隐状态一致的证明。

## 4. 编辑与继承

编辑器只看到当前策略及 learn 阶段的公开证据，不接收隐藏答案、任务标识或 gate/test 轨迹。每轮最多一次调用，返回新的 `when` 或不修改。动作核心与检索文本由程序保留。

候选在预先保留且未使用的 gate 任务上与旧库比较：每组仅选一个任务，预算按独立组数计算；两者均采用正常部署流程，从任务开头运行完整策略库。每个任务默认进行 3 次 Old/New 配对，交替顺序并记录原始分数；先计算任务内平均差值，再对独立任务等权平均。只有平均回报严格提高才继承；平局、任一次调用失败或父版本过期均拒绝。一次验证后，该组 gate 任务不得被后续候选再次使用。

门控只能筛选候选，不能证明普遍提升。少量验证任务上的正增益还需多随机种子和独立测试集确认，不能当成显著性检验。

## 5. 数据与指标

固定划分 `bootstrap / learn / gate / test`，同一任务族与近重复变体不能跨集合。代码检查 ID、组划分和重复游戏文件；语义近重复需在构建清单时正确标记。

bootstrap 成功轨迹通过独立命令一次生成共享初始库，保存来源和摘要；不同方法复用同一个 M0，不根据探测结果手动改写或筛选。正式 `run` 强制加载预生成库，不再自动 bootstrap；初始库摘要会记录，并可通过 `--expected-bank-hash` 校验。同一对比组必须使用相同 M0；无记忆对照使用空库。主实验固定初始策略集合。learn 用于正常执行及探测；gate 只决定候选继承；test 在方法冻结后只评测。无记忆和冻结初始库可由同一冻结评测入口运行，旧 v4 方法不作为基线。

分别报告首次任务成功率、冻结测试成绩、候选接受数、错误数及阶段成本。探测、编辑、双库门控、回放成本全部计入；无法取得用量的失败 API 请求标记 unknown。脚本演示结果仅作程序验证。

## 6. 与自进化的关系

进化对象是策略记忆的适用条件，反馈来自环境执行，继承受独立任务门控约束。模型参数、检索器、调度算法和记忆增删改查算法本身不进化，因此不宣称实现严格意义的递归自我改进（RSI）。

## 7. 代码状态与实验边界

实现目录：`/mnt/huawei/ymb/evomemory/evoscope/`。入口、文件职责、配置和产物格式见 [运行说明](../README.md)。

已实现初始化、策略存储、固定检索、状态回放、成对探测、条件编辑、独立门控、版本继承、阶段成本、冻结评测及 ALFWorld/EvolveLab 适配。离线回归测试使用合成环境和伪客户端；另已使用真实 DeepSeek V4.1 和 5 个 ALFWorld 游戏完成逐阶段小规模集成测试。发现并修复输出截断、JSON 模式和临时目录问题；实际探测中性、编辑 noop、门控只读验证，未验证真实接受更新的分支。详情见 [早期测试记录](LIVE_SMOKE_REPORT.md)，不作为方法效果结论。

第一阶段通过 `probe-only` 固定 M0，只验证干预信号与可重复性，禁止 edit/gate/update。全局默认最多 24 个 probe、每策略最多 3 个，跨 batch 累计且失败也占预算。预算耗尽后停止新批次，并记录未访问任务数。记录各策略在任务中的首次检索步、clean 数量与 seen 排除数量，只用于观察覆盖情况。报告逐策略正负效应、中性、不稳定及失败数量，不要求人为制造正负作用；审计恢复能力与范围错误后再开启进化，评估收益是否覆盖额外开销。完整消融、等预算对照、第二环境和跨模型实验属于后续实验工作，不用新增方法组件替代实证验证。策略增删与额外元控制器不纳入当前主方法。

## 8. 实验控制的实现约定

核心方法仍然是“固定动作核心的成对探测 → 仅编辑适用条件 → 独立完整库验证 → 通过后继承”。Gate 重复数、probe 配额、共享 M0 和输出上限属于必须预先固定并报告的实验配置，会影响成本与结果，但不引入新的记忆层、额外选择器或元控制算法。

正式命令与客户端的输出上限统一默认为 8192；同一方法对比组保持一致，截断仍记录为错误，不静默重试。发布源码使用 `evoscope.package_source` 的白名单工具，排除本机凭据目录 `.local/` 和环境文件。本轮改进仅用离线测试验证，不新增真实 API 实验。
